# Model comparison

Generated by `python scripts/build_reports.py` from the saved artifacts.
Every figure is measured, not quoted — rerun the command to refresh it.

All families are trained on the same rows, the same split and the same
seed, and ranked by **validation MAE in EUR**, which is the selection
metric (see [EXPERIMENT_TRACKING.md](EXPERIMENT_TRACKING.md) §4). Test
metrics are not shown per family on purpose: only the winner is scored
on the test seasons. Ranking every family on test would make the test
set a second validation set. Those seasons were nonetheless inspected
repeatedly during development, so the winner's test figures are
retrospective development evidence, not an untouched holdout
(see [EVALUATION.md](EVALUATION.md)).

Timings are wall-clock on one machine for one fit of the tuned
configuration, so they are comparable to each other and not to any
other machine.

## Reading this table

- **The spread is narrow.** Best to worst is 40% on the selection metric across 11 families. The signal in this data is in the features, not the estimator — which is exactly why the Phase 6 baseline was measured before any of this was built.
- **Cost breaks ties, and sometimes it is not close.** Extra Trees serialises to 1,519 MB against the winner's 2.1 MB — 720x larger — while scoring worse. Accuracy columns alone would not show why it was never a candidate.
- **`val MAE` selects; `cv MAE` explains.** The cross-validation column
  is the mean across expanding-window folds inside the training
  seasons. A family that looks good on one and poor on the other was
  lucky or unlucky on the single validation season.
