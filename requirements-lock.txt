# WHY BOTH THIS AND requirements.txt:
#   requirements.txt is the *declaration* — reasoned lower bounds and the one
#   upper bound that matters, each with a comment saying why. It is what
#   pyproject.toml publishes and what a human edits.
#   This file is the *resolution* — what CI and the Docker images install, so a
#   build today and a build in March install the same bytes. Without it, an
#   upstream release turns the build red with no commit to point at, and the
#   lint tooling being pinned exactly (requirements-lint.txt) while the entire
#   ML stack floated was an argument this project had already made and only
#   half applied.
#

#   uv pip compile requirements.txt --python-version 3.13 \
#       --output-file requirements-lock.txt
